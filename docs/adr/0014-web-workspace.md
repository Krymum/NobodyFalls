# 14. Front-end workspace

- Status: accepted
- Date: 2026-11-14

## Context

The game (a PWA) and, in phase 2, the admin are separate bundles (GAME_DESIGN §9)
that share the art direction and the character renderer (the admin previews
skins). The front end must stay small (150 KB of initial JavaScript, gzip) and
strict (TypeScript `strict`, no `any`, logic outside components).

## Decision

- `web/` is a **pnpm workspace**:
  - `packages/theme`: design tokens in TypeScript, the single source for canvas
    code and CSS. `tokens.css` (CSS custom properties) is generated by a script
    and a test fails when it is out of date; there is no CSS-in-JS at run time.
  - `packages/render`: the Canvas 2D renderers (ADR 0011, 0012). Framework-free.
  - `apps/game`: Vite + React. `apps/admin` comes in phase 2.
- Workspace packages are consumed as TypeScript sources (no build step); Vite and
  Vitest compile them.
- TypeScript 6 with `strict`, `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes`; ESLint with typescript-eslint `strictTypeChecked`;
  Prettier. One Vitest run covers every package.
- Dependencies are pinned to exact versions at least two weeks old.
- The production build is written into the API's `wwwroot`, so the API serves the
  game from the same origin (ADR 0007).

## Consequences

- The admin will reuse the renderers and tokens without duplicating them.
- Fonts are self-hosted (`@fontsource/barlow-condensed`): no request to a
  third-party font service.
